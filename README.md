# 청년상인 로우데이터 취합 자동화

담당자가 매달 원본 자료를 업로드하면 **전월 최종본 + 이번 달 발행리스트 + 채널 원본 데이터**를
합쳐 이번 달 로우데이터(취합) 엑셀을 완성하고, 전월 월간보고서 PPT를 함께 올리면 이번 달
PPT까지 만들어주는 Streamlit 웹앱입니다.

청년상인은 인스타그램(+블로그) 채널만 운영해서 LX세미콘 자동화보다 단순한 단일 흐름으로
구성했습니다(로우데이터 취합만 하며, AD 데이터도 같은 파일 안에 함께 채워집니다).

## 핵심 원칙

- **추측 금지** — 원본에 없거나 매칭이 애매한 값은 셀에 `확인 필요`를 직접 씁니다.
- **발행리스트 기준** — 발행리스트의 이번 달 발행건은 빠짐없이 행을 추가합니다.
- **전월 구조 복제** — 전월 최종본의 서식을 그대로 복제해 맨 아래에 이번 달 블록만 덧붙입니다.
- **기존 수식 보존** — 전월 최종본에 있던 수식(합계/평균/누적/증감률 등)은 절대 값으로
  덮어쓰지 않습니다. 이번 달에 새로 채우는 집계 셀도 전월과 같은 수식 패턴(SUM/AVERAGE/
  COUNTIF/SUMIF 등, 범위만 이번 달 위치로 조정)으로 써서 파일을 열면 전월 행과 새 행이
  서식·수식 모두 동일하게 보이고, 엑셀이 열릴 때마다 살아있는 값으로 재계산됩니다.

## 화면 구성

```
1 입력 파일       [전월 최종본: 로우데이터 xlsx / 월간보고서 ppt(참고용)]   [이번 달 발행리스트]
2 채널 원본 데이터 [인스타그램 콘텐츠 원본]   [인스타그램 AD 원본]  [제휴 오픈 보고서]
3 취합 실행       [취합 실행] 버튼 → 로우데이터(취합) 엑셀 다운로드
```

| 항목 | 형식 | 필수 | 비고 |
|---|---|---|---|
| 전월 로우데이터(취합) 최종본 | XLSX | ★ | |
| 전월 월간보고서 PPT | PPTX | | 현재 취합 로직에는 사용하지 않음(향후 PPT 자동화 대비) |
| 이번 달 콘텐츠 발행리스트 | XLSX | ★ | '인스타그램'/'블로그' 시트 |
| 인스타그램 콘텐츠 원본 | CSV, XLSX | ★ | 플랫폼 원본(Meta Business Suite CSV) 또는 NO/발행리스트 열이 있는 정리본 둘 다 지원 |

## 매칭 규칙

### 콘텐츠 ↔ 성과 원본
고유 링크(URL)로 매칭합니다. 인스타그램은 `/p/`와 `/reel/` 경로가 같은 게시물을 가리킬 수
있어 경로 종류를 무시하고 shortcode만 비교합니다.

### 콘텐츠 ↔ 광고
광고 소재명(`YYMMDD_제목`)의 날짜 코드는 **광고를 만든 날짜**이며 콘텐츠 발행일보다
1~2일 늦게 생성되는 경우가 흔합니다(실데이터로 확인됨: 같은 날 발행된 콘텐츠 2건에 대해
서로 다른 날 광고를 만든 사례). 그래서 날짜 근접도(±3일)와 제목 텍스트 유사도를 함께
점수화해서 매칭하고, 애매하면 `확인 필요`로 남깁니다.

- **광고비**(콘텐츠 시트) = 매칭된 광고의 실지출을 만원 단위로 올림
- **광고도달**(콘텐츠 시트) = 매칭된 광고의 '도달' 값 그대로
- **광고예산**(AD 데이터/AD 데이터(전체) 시트) = 원본에 캠페인별 예산 데이터가 없어,
  실지출을 만원 단위로 올린 값을 그대로 씁니다(예: 49,415 → 50,000, 98,879 → 100,000).
  AD 데이터(전체)의 '광고비(총합)'과 운영요약의 '연간 광고비 지출 현황'은 이 예산 값을
  SUMIF로 집계하는 살아있는 수식이라, 예산 값이 채워지면서 자동으로 맞는 합계가 됩니다.
- AD 데이터 시트 자체의 '지출 금액'은 원본 그대로(raw)를 쓰고, 만원 올림은 '광고예산'과
  콘텐츠 시트의 '광고비'에만 적용합니다(전월 최종본의 기존 규칙을 그대로 따름).
- '평균 도달당 비용'은 전월 최종본의 기존 수식 관례(`(지출÷결과)×1000`)를 그대로 따릅니다.
- 인스타그램/블로그 시트의 '유형' 열은 텍스트라 평균/합계 대상에서 뺍니다(전월 최종본도
  이 열은 비어 있음).

## 자동으로 채우지 못하는 항목(확인 필요로 남김)

- 블로그 콘텐츠의 조회/공감/댓글 — 이번 버전 입력에 블로그 성과 원본이 없음
- AD 데이터의 '타깃' — 원본에 없는 수기 항목
- AD 데이터의 '시작'/'종료' — 광고 원본에 개별 광고 단위 날짜가 없는 경우
- 채널 팔로워 시트 — 팔로워 일별 데이터 파일이 없어 이번 버전에서는 건드리지 않음(수기 유지)

## PPT 자동 채움

전월 월간보고서 PPT를 업로드하면(선택), 같은 실행에서 만든 로우데이터를 바탕으로 이번 달
PPT도 함께 만듭니다. 슬라이드 순서가 아니라 **표 헤더 내용**으로 표 종류를 인식하므로
슬라이드가 재배치돼도 동작합니다.

**자동으로 채우는 표** (LX세미콘과 동일한 3가지 대상)
- KPI 달성 현황 표(월별 발행수/도달수/조회수/참여수 + 누적/목표/달성률)
- 채널(인스타그램/블로그) 운영요약의 '전월 대비' 표(값 + 증감률, ▲빨강/▼파랑/확인필요 회색)
- 콘텐츠 발행 내역 표(제목에 발행 URL 하이퍼링크 포함, 이번 달 건수에 맞춰 행 자동 증감)
- 광고 진행 개요·참여/도달/동영상조회 캠페인별 내역 표, 예산 현황 표

**자동 채움 대상이 아님** (스크린샷·서술형이라 전월 내용이 그대로 남아있으니 직접 교체)
운영 캘린더, 팔로워 추이·성별/연령 차트, 우수 콘텐츠 TOP3(인사이트 문구), 블로그 검색
상위 노출 현황, 이벤트/인플루언서 제휴 소개 슬라이드.

## 제휴 데이터

인플루언서 체험단 콘텐츠는 청년상인 자체 채널 콘텐츠가 아니라 외부 계정 게시물이라
'인스타그램'/'블로그' 시트에는 섞지 않고, 별도 **'제휴'** 시트를 새로 만들어 이번 달
집행 내역을 이어붙입니다.

## 검증 현황

7월 최종 로우데이터 + 8월 발행리스트/채널 원본으로 8월 블록을 생성해 사람이 수기로 만든
8월 취합본과 대조했습니다. 인스타그램 콘텐츠 11건 전체(광고비·광고도달·조회·도달·좋아요·
댓글·공유·저장·팔로우), AD 데이터(참여/도달/동영상조회) 소계, 운영요약 KPI·광고비 지출
현황·월간 광고 요약 전부 일치를 확인했습니다.

같은 실데이터로 PPT도 생성해 KPI 표·채널 운영요약 표·콘텐츠 발행내역 표(하이퍼링크 포함)·
광고 진행 개요/내역 표가 로우데이터 값과 일치하고 증감률 계산(▲/▼)도 맞는 것을 확인했습니다.

**수식 기반으로 다시 만든 뒤에는 실제 Microsoft Excel(COM 자동화)로 파일을 열어 전체
재계산을 실행해서, 살아있는 수식들이 실제로 올바른 숫자를 계산하는지 직접 확인했습니다**
(운영요약 누적/KPI, 인스타그램 요약표 COUNTIF/SUMIF, AD 데이터 평균/합계, AD 데이터(전체)
SUMIF/SUMIFS 전부 사람이 만든 8월 취합본과 일치).

### 검증 중 잡은 버그(참고용)

- 전월 최종본의 여러 셀이 `=SUM(...)` 같은 수식이라 openpyxl로는 계산값을 못 읽음 →
  같은 파일을 `data_only=True`로 한 번 더 읽어 캐시된 계산값을 보조로 사용하도록 수정.
- 광고 소재명(`YYMMDD_제목`)의 날짜는 광고를 만든 날짜라 콘텐츠 발행일보다 1~2일 늦을 수
  있어, 날짜만으로 매칭하면 같은 날 발행된 다른 콘텐츠에 잘못 매칭됨 → 날짜 근접도와
  제목 유사도(최장 공통 부분문자열 비율)를 함께 점수화하도록 수정.
- PPT의 동영상조회 캠페인 표는 '노출'/'도달' 컬럼도 가지고 있어 도달 표 인식 조건과
  겹쳐 잘못 분류됨 → VTR 컬럼 유무를 먼저 검사하도록 순서 수정.
- **(2차 리뷰에서 발견) 취합 로직이 전월 최종본의 합계/평균/누적/증감률 수식을 파이썬이
  계산한 값으로 덮어쓰고 있었음** → 전체를 다시 설계해서, 이번 달에 채우는 집계 셀도
  전월과 같은 수식 패턴(범위만 이번 달 위치로 조정)으로 쓰도록 변경. PPT처럼 실제 숫자가
  필요한 곳은 셀을 다시 읽지 않고 계산 과정에서 이미 만든 파이썬 값을 그대로 전달.
- 위 재설계 과정에서 두 가지 계산 버그를 추가로 발견: (1) '영상 조회수'는 전체 콘텐츠의
  조회수 합이 아니라 유형이 '영상'인 콘텐츠의 조회수만 합산해야 하는데 전체를 더하고
  있었음(전월 최종본의 SUMIFS 수식을 다시 살려보면서 발견), (2) AD 데이터(전체) 시트의
  월별 광고비 SUMIF 수식에서 '월' 라벨이 있는 열 번호를 하나 잘못 짚어 다른 열에 씀.
- 이번 달에 새로 삽입한 평균/합계 행이 데이터 행과 같은 서식을 복사해 와서, 원래
  평균/합계 행에 있던 강조 배경색과 날짜 열 숫자 서식이 사라지는 문제 → 삽입 직후 전월의
  평균/합계 행 서식을 다시 덮어써 복원하도록 수정.
- 전월 수식 254개를 좌표 단위로 전수 대조하는 검사에서 2개가 더 발견됨: 운영요약의
  '참여 광고' 건수 증감(E37)과 '총광고비'(D49)는 다른 월간광고요약 행과 달리 전월
  최종본에서도 참조 수식(`=D37-C37`, `=C28`)이었는데 값으로 덮어쓰고 있었음 → 수식으로 복원.
- 인스타그램 시트의 '유형' 열(텍스트)에 합계/평균 수식(`=SUM(G..)`)이 잘못 들어가던
  버그 → 집계 대상 열 범위를 '광고비' 열부터 시작하도록 수정.
- '광고예산'이 원본에 없어 늘 `확인 필요`였던 것을, 실지출을 만원 단위로 올린 값으로
  채우도록 규칙 추가(캠페인별로 반올림 후 채움) → AD 데이터(전체)/운영요약의 예산 집계
  수식이 더 이상 0이 아니라 실제 값을 보여줌.
